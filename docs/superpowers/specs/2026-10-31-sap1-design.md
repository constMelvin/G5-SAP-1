# SAP-1 simulator design

## Intent

Build the coursework browser simulator in D:\Docs\SAP-1_Simulator_Project.docx. User accepted React + TypeScript + Vite and directed us to go build. Remaining choices below are proposed implementation decisions.

## Approaches

React/TypeScript/Vite provides reusable components and typed CPU state; plain HTML/CSS/JavaScript minimizes setup but needs manual synchronization. User accepted React. No server or database.

## Constraints and behavior

- 16-byte RAM; 4-bit PC/MAR; 8-bit IR, A, B, OUT; modulo-256 arithmetic with two's-complement subtraction.
- LDA=0, ADD=1, SUB=2, OUT=E, HLT=F. OUT/HLT ignore operand and editor emits EF/FF as in brief.
- Six microcycles: T1 PC→MAR; T2 PC increments; T3 RAM→IR; T4 IR operand→MAR; T5 RAM→A/B; T6 ALU→A for ADD/SUB. OUT uses T4 A→OUT; HLT stops at T4; other unused cycles idle.
- Expose logical active-high control signals, bus source/target/value, and explanations; not a gate-level or physical-polarity model.
- Step executes one instruction with microcycle playback; Clock does one microcycle. Run stops on HLT/error/pause, with safety pause after 256 instructions per run. Adjustable microcycle pace.
- Reset cancels timers, zeros registers/counters and restores last loaded RAM. Draft memory stays separate until Load succeeds.
- Editor supports mnemonics and raw hex/binary. Validate entire image before loading. Instruction template fills 0–4 only. User enters sample operands at 9/A/B; never hardcode these.
- Dark electronics workbench: memory editor, SAP-1 diagram with vertical W-bus, control signals, LEDs and bounded execution trace. Responsive panels and accessible labels.

## Non-goals

Accounts, database, cloud publication, extra instructions, decorative animation, and gate-level timing.

## Deliverables

Local app, source/lockfile, README, meaningful CPU/parser/browser tests, and three-case demonstration guide. GitHub publication and a student narrated recording remain external deliverables.

## Decisions and review

Unit 2 material was not supplied; timing assumptions above are documented. Use unsigned hex/binary with signed output interpretation. Disable editing during execution, display validation errors in text, distinguish draft from loaded RAM, and cap trace history.
